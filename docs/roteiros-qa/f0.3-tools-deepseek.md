# Roteiro de QA — F0.3 tools multi-turno DeepSeek

Data: 2026-07-22
Escopo: contrato Tool, DeepSeek V4 Pro/Flash, reasoning round-trip e replay.
Fora do escopo: execução de filesystem/bash, permissões, retry pós-efeito e loop autônomo da F1.

## Critério de pronto

O mesmo contrato deve:

1. enviar descritores puros de tools ao Pro e ao Flash;
2. remontar uma call SSE fragmentada, validá-la e aguardar um finish coerente antes de emitir o
   evento;
3. finalizar com assistant contendo `content`, `reasoning` e `toolCalls`;
4. aceitar o resultado associado pelo mesmo ID/nome;
5. serializar o segundo request com `reasoning_content`, `tool_calls` e `role: tool` intactos;
6. produzir a resposta final sem executar nenhuma função dentro do provider;
7. rejeitar requests/respostas inválidos sem rede indevida nem dados sensíveis na mensagem segura.

## Gate offline bloqueante

Usar Node 24.18.0 e remover chaves do ambiente:

- format, lint, typecheck e builds aprovados;
- tarball instalado offline e os dois bins testados;

## Matriz automatizada

| Área | Evidência bloqueante |
|---|---|
| Modelos | allowlist congelada e exata Pro/Flash, default Pro e ID arbitrário rejeitado |
| Request | tools únicas, nomes seguros, schema fechado e tool choice declarado |
| Schema | object/array/string/enum/number/integer/boolean; sem coerção, refs, accessors, símbolos ou propriedades extras/ocultas |
| Segurança JSON | ciclos, NaN, prototype keys, profundidade/tamanho em bytes e campos inesperados rejeitados; snapshots impedem TOCTOU |
| SSE | reasoning/text e argumentos fragmentados remontados; CRLF/keepalive/UTF-8 preservados |
| Calls | desconhecida/dinâmica, inválida ou ID duplicado falha fechado; evento fica em buffer até finish válido e é isolado do objeto final |
| Multi-turno | segundo body preserva reasoning, call ID/nome/args e resultado pelo ID correto |
| Replay | fixture de dois turnos estrita e copiada; mismatch não consome turno |
| Headless | tool call falha sem imprimir nome, ID, argumentos ou reasoning |
| Rede | fetch injetado, uma tentativa, abort antes/durante argumentos fragmentados, timeouts e HTTP sanitizados |

## Smoke real opt-in

Pré-condições:

- autorização humana explícita;
- fora de `CI`/`GITHUB_ACTIONS`;
- arquivo `0600` dedicado contendo somente `DEEPSEEK_API_KEY`;
- nunca versionar nem imprimir o valor.

Com a chave isolada no ambiente do processo:

```bash
CODINGPRO_REAL_SMOKE=1 pnpm smoke:deepseek
```

O script executa uma tool sintética e sem efeito colateral:

```text
usuário → V4 → somar({a:19,b:23}) → resultado 42 → mesmo V4 → "42"
```

São no máximo dois requests por modelo. A saída aprovada é somente:

```text
Smoke DeepSeek tools Pro aprovado.
Smoke DeepSeek tools Flash aprovado.
```

Resultado em 2026-07-22: aprovado nos dois modelos com thinking ligado, `tool_choice=auto` no
primeiro request e `none` no segundo. Não se exige reasoning não vazio no smoke pago; a
preservação byte a byte é comprovada deterministicamente pela suíte offline.

## Compatibilidade observada

Na API real, o V4 Pro respondeu HTTP 400 para `tool_choice=required` e escolha nominal enquanto
thinking estava ligado. A escolha automática passou no Pro e no Flash, e a escolha nominal passou
com thinking desligado. Até nova validação oficial, o adaptador rejeita localmente a combinação
forçada + thinking, evitando uma chamada paga destinada a falhar.

## Resultado

F0.3 aprovado localmente. O provider está pronto para ser consumido pelo futuro loop da F1, mas
continua deliberadamente incapaz de executar tools sem o sistema de permissão/checkpoint.
