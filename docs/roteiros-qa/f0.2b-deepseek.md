# Roteiro de QA — F0.2b adaptador DeepSeek

## Gate automatizado e offline

Nenhuma chave é necessária e nenhuma conexão externa deve ocorrer:

```bash
nvm use
pnpm install --frozen-lockfile
env -u DEEPSEEK_API_KEY -u OPENAI_API_KEY -u AI_GATEWAY_API_KEY pnpm check
```

Resultado desta rodada: 70 testes, cobertura por arquivo, typecheck, build e smoke do tarball
passaram. A suite injeta `fetch` e simula SSE; o pacote instalado continua usando replay.

Casos cobertos:

- request exato para `https://api.deepseek.com/chat/completions`, Bearer sintético e um POST;
- `deepseek-v4-pro`, thinking on/off, effort, reasoning multi-turno e ausência de `budget_tokens`;
- deltas de reasoning/texto, finish, usage/cache e resposta sem usage;
- 400/401/402/429/503, transporte, SSE inválido e nenhum retry automático;
- abort antes/durante o fetch e conteúdo não suportado rejeitado fail-closed;
- chave/body canário, callback de erro e controles de terminal não vazam.

## Gates do smoke real

Estes comandos **não chamam a API** e devem sair com código 1:

```bash
node scripts/smoke-deepseek.mjs
CODINGPRO_REAL_SMOKE=1 CI=true DEEPSEEK_API_KEY=canario node scripts/smoke-deepseek.mjs
```

Resultados esperados: o primeiro exige opt-in; o segundo recusa qualquer execução dentro de CI.

## Smoke real manual — requer autorização do operador

> Este passo faz uma chamada cobrada à DeepSeek. O script envia somente um prompt sintético
> pedindo `OK`; nunca envie código, dados de projeto ou informação sensível neste smoke.

```bash
pnpm build
CODINGPRO_REAL_SMOKE=1 \
  node --env-file="$HOME/.config/codingpro/deepseek.env" scripts/smoke-deepseek.mjs
```

Resultado esperado: `Smoke DeepSeek aprovado.` em stdout e código 0. A resposta, reasoning,
usage, headers e erros brutos nunca são impressos. Este passo não foi executado na rodada
automatizada de 2026-07-22.

O arquivo `deepseek.env` deve ter permissão `0600` e conter somente `DEEPSEEK_API_KEY`; não
carregue um arquivo compartilhado com credenciais de outros serviços.
