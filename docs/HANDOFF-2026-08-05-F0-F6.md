## 4. Detalhe dos itens de inteligência (o que cada um faz)

- **I10a** — bloco "Ambiente Windows" no system prompt: `bash` = cmd.exe (dir/type/where), one-liners Python multi-linha falham, usar `py -3`/Python312 `-E`, aspas em caminhos, encoding.
- **C9** — anti-varredura no loop (`agent.ts`): 12 passos seguidos só de leitura/bash disparam aviso de bússola ("leia skill/doc ou responda") antes do `maxSteps` (40).
- **I6b** — `repararInputToolCall` (`llm/src/validation.ts`): JSON com aspas simples / string JSON aninhada / chaves sem aspas são reparadas antes de virar `invalid-tool-call`. Fail-closed.
- **V1** — leituras puras do mesmo turno em `Promise.all` (`ToolGate.isReadOnly`); efeitos sequenciais na ordem; ordem dos resultados preservada.
- **V4** — `atualizarAutoEffort(estado, falhou, "rede"|"qualidade")`: falha de rede NÃO escala raciocínio.
- **C7** — teste de prefixo de cache byte-idêntico (nada volátil no system prompt).
- **C3** — dedup no `ToolRegistry`: mesma tool+input idêntico na sessão devolve "mesmo resultado da leitura #N"; efeito invalida cache.
- **C1** — compactação com resumo determinístico (sem LLM): arquivos tocados + decisões + pendências, posição `[system][resumo][sufixo]`. Ligado no `/compact` e auto-compact (desktop) e `/compact` (CLI).
- **I4** — `montarSystemPromptDesktop` injeta índices de memória (global+projeto) + top-K relevantes à última mensagem (~300 tok). Paridade CLI.
- **I5** — repo_map âncora: 1º turno com projeto detectado injeta repo_map resumido (1,5k tok, 400 arquivos).
- **O1/O3/O4** — task tool: leitura ≤6 paralelos / efeito ≤2; mesma tarefa de leitura reusa relatório na sessão; >3 tarefas → 400 chars cada.
- **I9a** — skills semeadas: `docs/skills/segundo-cerebro.md` + `docs/skills/windows-env.md` (fonte canônica) e copiadas para `~/.codingpro/skills/` (onde o desktop lê global). Frontmatter `name`/`description`.
